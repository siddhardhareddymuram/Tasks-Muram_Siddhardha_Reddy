# Module 6 : Practicing Piping

* ### Redirecting output

![image](https://github.com/user-attachments/assets/6f13fac0-a217-48cd-8e27-4710f7b7312d)

The `>` operator is used to redirect the output of a command into a file.
Here, the output **PWN** is redirected into the file **COLLEGE**.

* ### Redirecting more output

![image](https://github.com/user-attachments/assets/6650a0c5-b550-4151-8cbd-5736e40b985d)

The output generated by `/challenge/run` is redirected into the file **myflag** using `>`.
This allows us to store the flag in a file instead of displaying it directly in the terminal.

* ### Appending output

![image](https://github.com/user-attachments/assets/e4638333-e19f-442b-a058-c93dd36e825f)

![image](https://github.com/user-attachments/assets/fbfd5395-6ec2-4bbe-a157-c93dd36e825f)

The `>` operator creates or overwrites a file with new output, while `>>` adds output to the end of an existing file.
In this challenge, the first part of the flag is written using `>`, and the remaining part is appended to the same file using `>>`.

* ### Redirecting errors

![image](https://github.com/user-attachments/assets/97fbcbee-b675-42e3-9452-f171224a1b63)

Linux separates normal output and error messages into different streams.
Here, the error/instruction output from `/challenge/run` is redirected into **instructions**, while the required output is stored in **myflag**.

* ### Redirecting input

![image](https://github.com/user-attachments/assets/8013893d-5668-40cd-9725-3291ad9ac07f)

First, the output **CHALLENGE** is written into the file **PWN**.
The contents of this file are then supplied as input to `/challenge/run` using the `<` operator.

* ### Grepping stored results

![image](https://github.com/user-attachments/assets/ee8b93be-609e-4458-8c0b-2a7d2b9360a7)

The output of `/challenge/run` is first saved in `/tmp/data.txt`.
We then use `grep` on the stored data to search for the required flag.

* ### Grepping live output

![image](https://github.com/user-attachments/assets/e8439aac-12e0-4038-b04e-74f2d9288d64)

The pipe operator `|` allows the output of one command to be passed directly as input to another command.
Here, the output of `/challenge/run` is piped directly into `grep`, allowing us to find the flag without storing the output in a file first.

* ### Grepping errors

![image](https://github.com/user-attachments/assets/1b6fb6ba-c391-4ad8-8f16-101726ae6a4d)

The `2>&1` syntax redirects standard error (`stderr`) to standard output (`stdout`).
This combines both streams, allowing `grep` to search through the complete output and locate the flag.

* ### Duplicating piped data with tee

![image](https://github.com/user-attachments/assets/cf734f88-10ef-4cd5-9a6f-c10ed651e0af)

The `tee` command is useful when we want to pass data through a pipe while also keeping a copy of it.
Here, `tee` captures the output, allowing us to obtain the secret code while simultaneously passing the data to `/challenge/college`.

* ### Writing to multiple programs

![image](https://github.com/user-attachments/assets/7dbcadf6-6e53-4be7-a4df-4514fb4e5816)

Process substitution `>()` allows the output of a command to be treated as input for another program.
By combining `tee` with process substitution, the same output can be sent to multiple programs at the same time.

* ### Split-piping stderr and stdout

![image](https://github.com/user-attachments/assets/a9e6fe69-695b-44c5-9788-c3461f013baf)

Standard output and standard error can be redirected separately.
Here, `1>` and `>()` are used to handle `stdout`, while `2>` and `>()` handle `stderr`. This allows both streams to be sent to different programs and helps us obtain the flag.
